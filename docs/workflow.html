The FrontierPhysics Workflow at a Glance 🚀

In one sentence: together we build real, hard, verifiable frontier-physics research tasks that measure the research ability of AI agents.

🎯

Core goal

Every task is a real research project (about the scale of one paper), runs end-to-end in a computational environment, and challenges SOTA agents.
Verifiable grading plus research-behavior rubrics hold both the result and the process to a bar you would show a senior researcher.

1

What is worth submitting (think this through first)

A real research project

From your own research, ideally the scope of a paper. Multiple valid solution paths welcome.

Completable in a computational environment

Every step runs in the sandbox — no wet lab. If experiments are essential, mock the device (e.g. env0) or grade the planning stage instead.

Challenging for agents

Not searchable, not solvable in minutes. Local runs and review — not gut feeling — decide what counts as hard.

2

What you own

The task itself

Define the research question, background, data/environment, and deliverables. An agent may help along the way — but task.md and rubric.json must be hand-written: you write, polish, and confirm the final text yourself.

Verifier + rubric (grading & review standards)

The verifier grades the result; the rubric grades the research behavior. You design both — and you sign off on both.

3

Verifier vs. rubric

Verifier: checks the result (result correctness)

Automated, verifiable checks that the result is scientifically correct: numerical tolerances, file structure, figure contents.

Rubric: checks the process (research behavior)

LLM-judged review of how the research was done — professional, solid, reproducible, no cheating:

  • Blockers: serious problems or cheating (e.g. guessing the answer without doing the computation)
  • Non-blockers: quality dimensions, weighted and scored 0–2
4

Iterate and polish locally

Run agents locally and watch how they fail. Sharpen the task, verifier, and rubric until they discriminate.

5

Self-check and align

Self-review with the task-review skill and the merged good-task PRs. Survive an adversarial review, then open the formal PR.

6

Formal PR and review

Auto review clears format and completeness blockers; human review then debates the science, difficulty, and rigor — iterate until merge.

7

What reviewers check (in order)

1

Good format

The task and the PR follow the standard format — task example: PR #109.

2

Authentic environment

environment/ holds real research files in the most original formats used in research — not AI-vibe made-up data. AI-generated content has clear patterns (weird file formats to represent data, etc.).

3

Clean components

No weird files in environment/, verifier/, or oracle/ — stray files are a strong sign of AI-generated tasks without human audit. Using agents to develop is fine; humans must fully check the final content.

4

Real project, end to end

From a research project the contributor did themselves, covering that project end to end. One paper to one task is ideal; real end-to-end projects without papers are also good candidates.

5

Human-written text

task.md and rubric.json are human-written and human-polished — reviewers check with tools like GPTZero.

6

Referenced rubric

Every item in rubric.json carries a solid reference from the contributor, supporting its blocker / non-blocker choice.

7

Peer-review bar

The verifier and rubric logic represent academic peer review: if an agent passes the verifier plus blocker rubrics, the deliverables should be publishable or presentable to senior researchers without harming your reputation.

8

Hard for SOTA agents

The final experiment provides no skills to the agent. Indications of a challenging task: 500+ steps to finish; agent results that cannot pass peer review or that you would not show your colleagues.

9

No false verdicts

You can show the verifier and rubric logic produce neither false positives nor false negatives.

10

Final deliverables only

Deliver only the files you would use for a peer-review submission, or presentable results you would proudly share (paper.pdf, report.pptx). Do not include process files like PLAN.md — the example task has been replaced accordingly.

Open a draft PR early and start the conversation — don't submit right before a deadline.
Keep everything reproducible, verifiable, and auditable.
Judge difficulty from local-run data, not subjective impressions.
Science and authenticity first; implementation and formatting second.

FrontierPhysics 工作流程速览 🚀

一句话定位：我们一起构建真实、困难、可验证的前沿物理研究任务，用于评估 AI Agent 的研究能力。

🎯

核心目标

每个任务都来源于真实研究项目（尽量对齐一篇论文的体量），在计算环境中可端到端完成，对 SOTA Agent 具有挑战性，
通过可验证的判分与研究行为（rubric）确保结果与过程都达到“可发表/可显现给资深研究者”的标准。

1

什么样的任务值得提（先想清楚）

真实研究项目

来源于你的真实研究，尽量覆盖一个
paper 的体量（从问题定义到结论），
也可以包含多个合理的 inference 路径。

可在计算环境中完成

任务的所有步骤都可以在计算环境中
完成（无真实实验依赖）。如需实验，
可使用可信的模拟/Mock（如 env0）
或聚焦研究与规划阶段。

对 Agent 有挑战性

不能过于简单：不能直接搜到答案，
也不应在几分钟内被轻松解决。
是否“足够难”，由本地运行结果与
评审共同判断。

2

你主要负责什么

Task（任务本身）

清晰定义研究问题、背景、数据/环境、交付物和预期贡献。
过程中可以让 Agent 协助，但 task.md 与 rubric.json 必须由你亲手撰写，
逐字打磨并最终确认，避免幻觉与偏差。

Verifier + Rubric（判分与评审标准）

设计可验证的客观判分（verifier）和评审维度（rubric）。
Verifier 看结果是否正确；Rubric 看研究行为是否专业。
同样需要你把关与最终确认。

3

Verifier 与 Rubric 的区别

Verifier：检查结果（Result Correctness）

自动化、可验证的判分逻辑，判断提交结果是否满足科学与
工程上的正确性要求（如数值误差、文件结构、图表内容等）。

Rubric：检查研究行为（Research Behavior）

由 LLM 评审的维度，评估 Agent 的研审过程是否专业、扎实、
可复现、无作弊等。Rubric 分为：

  • Blocker（阻断项）：严重问题或作弊行为（如未做计算直接猜答案）
  • Non-blocker（计分项）：质量维度，按权重评分（0-2 分）
4

本地迭代与打磨

多用本地运行观察 Agent 的表现与失败模式，据此完善 task、verifier 与 rubric，提高区分度。

5

自检与对齐

用 task-review skill 自检，参考 good task PR，通过 adversarial review 后提交正式 PR。

6

正式 PR 与评审

自动检查清掉格式与完整性 blocker 后，真人评审讨论科学性、难度与判分严谨性，迭代至合并。

7

评审时会依次检查什么

1

格式规范

任务与 PR 遵循标准格式——示例任务：PR #109。

2

环境真实

environment/ 中是真实科研环境与文件，采用科研中最原始的文件格式，而非 AI 编造的数据。AI 生成内容有明显模式（例如爱用奇怪的文件格式存数据）。

3

组件干净

environment/、verifier/、oracle/ 中没有多余杂项文件——那是任务由 AI 生成且未经人工审核的强烈信号。开发时可以用 agent，但最终内容必须经人工全面检查。

4

真实且端到端

来自贡献者亲身完成的真实研究项目，并端到端覆盖该项目。一篇论文对应一个任务最理想；没有论文的真实端到端项目同样合适。

5

人工撰写

task.md 与 rubric.json 由人撰写并润色——评审会用 GPTZero 等工具检查。

6

评分项有依据

rubric.json 每一项都有贡献者提供的可靠参考文献，支撑其 blocker / non-blocker 的划分。

7

同行评审门槛

verifier 与 rubric 的逻辑要能代表学术论文同行评审的标准：agent 通过 verifier 与 blocker 评分项后，交付物应当“可发表/可展示”给资深研究者而不损害你的学术声誉。

8

对 SOTA agent 足够难

正式实验不向 agent 提供任何 skill。困难任务的参考信号：完成需 500+ 步；agent 的结果达不到同行评审水平，拿给同事看会损害你的声誉。

9

无误判

能证明 verifier 与 rubric 逻辑既无假阳性也无假阴性。

10

只交付最终成果

最终交付物只应包含你会用于论文投稿评审的文件，或可自豪分享给同事的成果（paper.pdf、report.pptx）。不要包含 PLAN.md 之类的过程文件——示例任务已相应更新。
